# 《GBA 模拟器内核源码精讲》系列设计文档

> 基于 libretro-mgba 源码的中文 manim 讲解视频系列。
> 日期：2026-06-07 ｜ 作者：Hamber

## 1. 背景与动机

很多人会说「我不懂模拟器内核开发，只是做做 UI」。本系列通过精读 mGBA（libretro-mgba 仓库内含完整内核源码，而非仅 libretro 壳）的源码，把模拟器内核这件「看起来很硬核」的事讲透——证明它是可以被理解、被讲清楚的。

本仓库已确认包含完整 mGBA 内核：CPU 核（`src/arm`，ARM/Thumb 解码与执行）、GBA 子系统（`src/gba` 下 video/audio/dma/timer/memory/io 等）、core 抽象层（`src/core` 下 timing 调度、serialize 存档）。规模适中，适合系列化讲解。

## 2. 核心调性：深入浅出 · 双层结构

「都要、深入浅出」是一种明确的内容结构选择，不是和稀泥。每一集采用**双层结构**：

- **表层**：给认知爽感——这是什么、为什么妙。面向泛技术观众和应用开发者。
- **里层**：给硬核实现——mGBA 源码怎么写、为什么这么设计。面向懂底层 / 想自己写模拟器的人。

manim 负责画直觉（动态时序、数据流），旁白 + 代码特写负责补深度。两层在同一集内并行，观众各取所需。

## 3. 叙事主线

**主干**：跟着「一帧画面的诞生」走完整条数据流——按键 → CPU 取指/执行 → 改内存/显存 → DMA 搬运 → PPU 扫描成像 → 屏幕点亮 → APU 出声。

**钩子**：主线经过某个环节时，自然抛出该环节的经典模拟器难题（如讲到 CPU 时序就引出「周期精确」，讲到启动就引出「没有真 BIOS 怎么跑」）。

这样系统性（主线不迷路）和悬念（每集自带钩子）兼得。

## 4. 制作规格

| 项 | 规格 | 说明 |
|----|------|------|
| 画幅 | **16:9 横屏** | 代码特写、宽幅时序图/流水线动画需要横屏；竖屏会很憋屈 |
| 分辨率/帧率 | 1080p / 60fps | 延续现有频道规格 |
| 单集时长 | 中等深度集 8-15 分钟；序章/概览集更短 | **注意 +50% 语速的压缩效应**：90-110 句口语短句在 1.5 倍速下约 4-5 分钟。要做到 ~14 分钟，深度集需 ~250-300 句并含代码逐段讲解。Pilot 序章实测 ~5 分钟，作为轻快开篇是合适的 |
| 系列长度 | 10 集（第 1 集为 Pilot） | |
| 语言 | 中文普通话 | |
| 配音 | `zh-CN-XiaoxiaoNeural`，语速 `+50%`，句间停顿 0.30s | 延续 `doc_to_video` 默认 |
| 字幕 | 无底部字幕 | 画面干净 |
| 中文字体 | macOS `Heiti SC` | |
| 视觉风格 | **延续现有频道（风格 C）** | 复用 `doc_to_video` / `daily-crypto` 视觉资产，保持频道品牌统一 |

### 4.1 产线（复用 doc_to_video）

四步流水线，每步独立产物可单独重跑：

```
①读源码/写大纲 → ②写口播稿 script.md → ③逐句配音 voice.mp3 + timeline.json → ④manim 按绝对时间轴对齐并合成 mp4
```

对齐原理：第③步逐句单独合成、记录每句精确时长写入 `timeline.json`；第④步 manim 每句动画严格占满对应秒数，零累积误差。沿用 `references/scene_template.py` 的 `P()`/`W()`/`sync_to()`/`beat()` 机制，原样照搬，只改视觉内容。

### 4.2 相对 doc_to_video 的产线差异（避坑）

`doc_to_video` 默认是「3 分钟精华概览版」，本系列是 14 分钟深度讲解。需在产线上扩展：

1. **时长**：单集 ~14 分钟，远超默认 3 分钟。口播稿和场景数量相应放大。
2. **单集结构**：采用「分段 → 场景」的固定结构（见 Pilot 分镜），而非概览版的「主干即全部」。
3. **两个新增视觉模板**（本系列专用，需在 Pilot 中定型并沉淀为可复用模板）：
   - **代码特写卡片**：展示 mGBA 真实源码片段的统一样式（等宽字体、高亮行、文件名标注）。
   - **数据流动画**：数据沿模块间流动、逐站高亮的统一样式（流水线、扫描线、总线抢占等都用它）。

## 5. 系列大纲（10 集）

| # | 标题 | 主线位置 | 钩子难题 | 源码锚点（已核实存在） |
|---|------|---------|---------|----------------------|
| 1 (Pilot) | 序章：一帧画面是怎么诞生的 | 全链路鸟瞰 | 模拟器到底在模拟什么 | `src/gba/core.c` / 全局 |
| 2 | CPU：如何用软件假装成一块 ARM7 芯片 | 取指→解码→执行 | 解码慢？查表法 | `src/arm/arm.c`、`decoder-*.c` |
| 3 | 一条指令的执行：Thumb 指令集实战 | 执行→写回 | 周期从哪来 | `src/arm/isa-thumb.c`、`isa-arm.c` |
| 4 | 内存不是数组：MMIO 与地址映射 | CPU 读写内存 | 一次访存几个周期 | `src/gba/memory.c` |
| 5 | 时间的主宰：周期精确与事件调度 | 贯穿全局的「时钟」 | 怎么做到周期精确 | `src/core/timing.c` |
| 6 | DMA：不打扰 CPU 的搬运工 | 内存→显存的高速搬运 | DMA 凭什么抢总线 | `src/gba/dma.c` |
| 7 | PPU：扫描线是怎么画出来的 | 显存→像素 | 软件渲染 vs 硬件 | `src/gba/video.c`、`src/gba/renderers/` |
| 8 | 没有真 BIOS，游戏怎么还能跑？ | 启动与系统调用 | HLE 高级模拟 | `src/gba/bios.c`、`hle-bios.c` |
| 9 | 声音：4+2 个声道如何合成一帧音频 | 像素之外的另一条线 | 音视频同步 | `src/gba/audio.c`、`timer.c` |
| 10 | 随时存档读档：把整台机器冻在一瞬间 | 状态快照 | 状态序列化的坑 | `src/core/serialize.c` |

**排序逻辑**：
- 第 2-3 集是主线最硬的部分（CPU），紧跟序章建立的「全局地图」之后，观众有地图就不会迷路。
- 第 5 集「时间的主宰」是承重墙——`timing.c` 的事件队列调度贯穿所有模块（已核实其为 `root`/`nextEvent` 链表式事件调度器），放在中间承上启下。
- 第 9 集音频作为「像素之外的另一条线」，与前面的视频主线形成对照，引出音视频同步。

每集后续各自走「spec → plan → 实现」循环，本文档先聚焦 Pilot。

## 6. Pilot 详细设计：《序章 · 一帧画面是怎么诞生的》

### 6.1 目标

1. 给观众一张贯穿全系列的「全局地图」。
2. 跑通整条产线（脚本 → manim → TTS 对齐 → 成片），并定型两个新视觉模板。
3. 当系列名片，让人想追下去。

**策略**：避开最难的代码（CPU 指令实现留到第 2-3 集），重表现力、轻实现细节。

### 6.2 时长与调性

~14 分钟。表层讲「按一个键到画面亮起，机器内部发生了什么」；里层在每一站点一下对应的 mGBA 文件，预告后面每一集对应主线的哪一站。

### 6.3 分镜（manim 场景划分）

| 段 | 时长 | 内容 | manim 表现 | 双层 |
|---|------|------|-----------|------|
| 0 开场钩子 | 0:00-1:00 | 一帧马里奥跳起的画面定格，抛问：这 16ms 里机器做了几百万件事 | 画面定格 → 碎成数据流粒子 | 表 |
| 1 什么是模拟 | 1:00-3:00 | 真机 = 一堆芯片在跑；模拟器 = 用软件复刻每块芯片的行为。**并排展示精简版 `struct GBA`**，让里层观众第一集就尝到源码味道（点到为止，不逐行讲） | 真机芯片图 ↔ 软件结构体并排；代码特写卡片首次登场 | 表+里 |
| 2 主角登场 | 3:00-4:30 | GBA 五大件：CPU(ARM7)、内存、PPU、APU、DMA + 一根「时钟」 | 五个模块卡片亮相，标注源码文件名 | 里 |
| 3 一帧的旅程① | 4:30-7:30 | 按键 → CPU 取指执行 → 改显存（主线前半） | 数据沿流水线流动，逐站高亮（数据流模板首次登场） | 表+里 |
| 4 一帧的旅程② | 7:30-10:30 | DMA 搬运 → PPU 扫描线 → 屏幕点亮 → APU 出声 | 扫描线从上到下画出画面 | 表+里 |
| 5 隐形的主宰 | 10:30-12:30 | 这一切凭什么对得齐？——「时钟/周期」统领全场，引出 `timing.c` | 所有模块叠加一条统一时间轴 | 里 |
| 6 系列地图 | 12:30-14:00 | 把刚走过的路标成 10 集地图，每集挂在哪一站 | 全景地图，10 个站点点亮 | 表 |

### 6.4 Pilot 要验证 / 定型的事

- manim 脚本能否由 AI 生成并渲染通过（先跑段 0-1 验证风格）。
- TTS 逐句对齐机制是否顺畅（复用 `doc_to_video` 的 `build_audio.py` + `timeline.json`）。
- 视觉风格 / 配色 / 旁白语气是否满意——Pilot 就是用来定调的。
- **两个新视觉模板（代码特写卡片、数据流动画）在 Pilot 中定型，沉淀为后续 9 集可复用的模板。**

## 7. 不做什么（YAGNI）

- 不做竖屏 / 多版本剪辑。
- Pilot 不深挖任何单模块代码（深挖留给后续集）。
- 不在 Pilot 引入交互式浏览器 mockup——manim 即成片，规划阶段用文字 + ASCII 即可。
- 暂不规划第 2-10 集的逐集分镜——每集到自己的 spec 阶段再展开。
